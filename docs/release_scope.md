# 正式软件与本地二维实验的边界

正常使用场景为用户选择一个离子模式，在同一 LC 方法下对普通样本执行特征提取、峰对齐、MS2 鉴定和结果整理。2026-09-20 已合并为项目 GUI / project-run 的串行自动入口。

2026-09-05 用户确认：当前 132 文件的二维数据是特殊实验，最终上传的软件版本不需要该实验的专用处理代码。

正式运行核心位于 `src/lipidgate/` 与被它复用的 `src/lipidbench/`。运行所需的谱库应由正式分发流程提供；真假峰模型不再是产品依赖。`pyproject.toml` 的包发现只扫描 `src/`；二维 runner、比较器、样本数据和实验输出都不是正常 GUI/CLI 的依赖。

以下属于本地专项验证，不应加入正常软件的菜单、必填参数或默认运行链：

- 二维分段及分段起始 RT 归一化。
- 特殊重复分段的替换规则。
- 本批次正负模式、碰撞能、分段结果合并。
- 132 文件 manifest、原始 mzML 缓存和历史比较结果。
- `scripts/run_2d_reanalysis.py`、`scripts/compare_2d_reanalysis.py` 及其他 `*2d*` 专项脚本。

这些资料在本地保留，以便复核本轮结论。`.gitattributes` 已把 `scripts/*2d*` 和 `outputs/` 标为 `export-ignore`，标准 `git archive` 源码导出会排除它们。该规则不删除本地文件，也不改变直接推送整个 Git 仓库的内容；最终源码上传应使用经过核对的发布导出，而不是未经筛选的工作目录。

单模式多文件可以在一个进程内共享同一个只读 MS2 搜索器和谱库；不同文件持有各自的谱图与结果。是否启用多线程应由实测决定，必须先确认与串行的候选、分数、碎片和前体校正审计一致。二维脚本中的线程试验本身不成为产品依赖；若后续证明有稳定收益，再把通用批处理接口用于正式工作流。

2026-09-24：正式多文件 MS2 流程增加 1–4 进程选择，默认仍为单进程。每个子进程加载独立谱库，搜索结果按输入顺序回到主进程，再做特征关联和最终筛选。线程试验仍不进入产品。运行前按谱库规模估算所需内存，不足时拒绝启动并提示减少进程数；见 `docs/parallel_ms2_20260924.md`。
