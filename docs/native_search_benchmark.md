## 与 LipidIN 原生 C++ 比较计时范围

此次实际编译并运行官方 R 版的 `EQ.cpp` 与 `SpeedKing.h`，通过 Rcpp 调用原始 `Comparator.Compare()`，未修改 EQ 算法。此前图中 `LipidIN_EQ` 是 Python 移植版本，不能当作本次原生实现的速度。

| 每 1,000 张 MS2 的阶段 | 正离子 | 负离子 |
| --- | ---: | ---: |
| LipidGate C ABI 数值内核 | 7.933 ms | 13.347 ms |
| LipidGate 数值阶段，含块读取和缓冲准备 | 496.713 ms | 503.340 ms |
| LipidIN 原生 EQ 查询 | 13.666 ms | 27.103 ms |
| LipidIN 一次性载入 | 1.09 s | 0.97 s |
| LipidIN 最后一次结果写出 | 0.150 s | 0.150 s |

内核计时包含 C ABI 调用，排除缓冲准备、块读取、门控、结构解释和最终排序；数值阶段禁用碎片预筛选，共处理 25,272 / 25,567 个前体候选。LipidIN EQ 的查询计算其两个基础匹配分数并添加结果，未执行 LipidIN 的整套后续注释流程。两种算法的匹配选择、去重和分数定义不同。因此既不能将 `3 秒 / 0.014 秒` 解释成完整软件速度差，也不能仅凭内核时间宣称算法优劣。

LipidIN EQ 的三轮查询秒数分别为正离子 `0.0137533, 0.0136657, 0.0131770`，负离子 `0.0288246, 0.0264403, 0.0271025`。结果对数为 21,032 / 22,698；每个前体候选又用原始 `CompareMS2` 独立核对，结果键及数量相同，CSV 六位小数的分数误差不超过 `1e-6`。载入使用二进制适配器，避免先构造百万个 R 列表；R 列表构造时间未计入。

LipidIN 此测试一次展开整库，最大的 R 工作进程 RSS 为 779.6 / 787.3 MiB，整个进程家族峰值约 802.0 / 809.7 MiB。读取的是同一组归一化记录，按原 EQ 要求排序前体和碎片；不是另换更小的库。

原始源码固定在 [LipidIN 官方检查点](https://github.com/LinShuhaiLAB/LipidIN/tree/abfd9201a40d56a8dde8fae1fff5898403c64c65/LipidIN%20for%20R%20%2820250601%29/LipidIN%204-level%20hierarchical%20library)，`EQ.cpp` SHA-256 为 `b2b9b6138233935fc608f2fe9eb452542485b05a3082a2cb25e73530b80f9172`，`SpeedKing.h` 为 `c5c986f9d097501159b7513b7916122a5c6b4431930586bb0ff656a0ea2e4a76`。它们不打包进 LipidGate。

## 格式、内存和实现选择

运行索引由 format 2 的 122,961,920 bytes 改为 format 3 的 117,481,472 bytes，合计减少 4.46%。两库的全部 2,346,939 条归一化记录及前体索引逐项验证一致。重复碎片出现次数、顺序、名字、权重、必需证据组和元数据都保留；压缩 MSP 内容及其校验值未改变。

程序保留至多四个 1,024 条记录块的解码缓存，数值视图随对应块释放。候选少于 128 条时直接使用编译后的原策略路径，避免 C ABI 准备成本抵消收益；较大候选集才调用批量内核。用户设置的 m/z、类型和加合物限制继续生效。

策略扩展由 Cython 3.3.0 直接生成 C++，仍保留 Python 对象及 NumPy 运算；并非把所有代码改为裸 C++ 数值类型。关闭类型推断、注解类型转换、fast-math 和 FMA 收缩，保护容差端点、强度并列、去重及 float32 行为。缺失、不兼容或源码修改后的扩展使用 Python 路径；Windows 下载版内置已验证扩展，无需用户安装编译器。生成扩展的机制见 [Cython 官方说明](https://cython.readthedocs.io/en/latest/src/userguide/source_files_and_compilation.html)。

## 实验条件与复现

- Intel Core i5-13400F，Windows x64，固定逻辑 CPU 0；Python 3.13.5、GCC 14.3.0、Cython 3.3.0、R 4.5.2、Rcpp 1.1.0。
- 数据来自 `positive-mode test file` 和 `negative-mode test file`，分别准备出 3,637 / 2,199 张 MS2，随机种子 2026 取各 1,000 张，再稳定按前体质量排序。
- 前体 5 ppm、碎片 15 ppm、Top 3、最低分 50、最低相对强度 0.002；保留默认正离子 PS/LPS 铵加合物排除，未加其他类型或质量范围限制。
- GC 开启；各轮重新创建检索器和解码缓存，保留系统文件缓存；按不同次序交替跑三种实现，避免固定先后次序。计时试验顺序执行，不与构建或其他测试并发。
- CPU 14 的探索结果不作为本文结论，其中后续运行存在与另一数值试验重叠的问题。后台系统负载仍可能造成波动；表中速度只适用于这些输入和计时范围。

通用完整检索复现入口为 `scripts/benchmark_ms2_search_perf.py`，构建入口为 `scripts/build_native_search.py`、`scripts/build_native_policy.py`。强制源码策略时，在新进程设置 `LIPIDGATE_PYTHON_POLICY=1`；`--disable-native` 只关闭批量内核，并不会关闭策略扩展。

准确的历史查询、结果快照、旧索引、原生 EQ 适配器、逐轮 JSON 和日志在项目外的研究归档中保存。公开仓库仅包含实现、回归测试和本文，不包含原始样本或生成的巨型二进制输入。最终构建指纹和冻结程序验证记录随版本发布。

## 旧图“最快”与当前排名变化的核对

2026-10-23核对旧六方法实验记录、作图表和统一协议后，旧图中“LipidGate最快”
不能解释为实际生产检索最快。旧图计时对象是简化fast适配器，并未执行生产
检索中的完整证据规则；把该图概括成完整LipidGate查库最快，属于不成立的结论。

| 项目 | 旧正负独立ECDF/箱线图 | 当前统一检索协议 |
|---|---|---|
| LipidGate | 简化fast评分适配器；未运行完整证据规则 | 实际候选检索、碎片匹配、原有评分/门控、排序和内存Top20 ID/分数 |
| LipidIN | 原生EQ的逐谱适配路径 | 官方Rcpp EQ原生批处理路径，保留两个评分分量及Top20生成 |
| 强度输入 | 等强谱 | 保留固定公共清谱后的真实相对强度 |
| 统计对象 | 每张谱9组、每组16次调用，得到逐谱耗时分布 | 100个完整批次，每批总耗时除以1,000张输入谱 |

两套统计均保留无候选查询和耗时长的查询，但逐谱中位数与批次平均时间的
中位数并非同一指标。例如旧表正模式LipidGate的逐谱中位数为0.2875 μs，
同一旧表的均值为2.9618 μs；这两项又都来自简化适配器，不能与当前完整
规则检索的88.986 μs直接相除。输入强度与原生调用方式也同时发生了变化。
更早的合成扩库/纯数值内核实验同样不能代表实际生产评分与门控的耗时。

当前协议不包含MS1、LCI/ECN、文件读取/导出、界面或逐峰证据JSON序列化；
排名改变不能归因于把这些步骤加进了当前计时。各方法执行自己的原有评分，
规则检索和相似度检索承担的计算工作不同，因此速度排名也不代表鉴定质量。
