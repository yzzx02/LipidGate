# 2026-09-28 正模式内存、ECN 与结果核对

测试样本：`D:\脂质匹配算法软件\dataset\LargeIntestine\Pos`。所有临时脚本、日志、CSV 和截图位于 `.test_outputs/parallel_tests_20260924/`，可统一删除；原始 mzML 未修改。

## 正模式库内存

原缓存含 1,262,204 条解析记录及 9,485,860 个碎片对象。原 Python dataclass 的实例字典带来大量对象开销；给库记录和碎片记录使用 `slots`，兼容旧 pickle 缓存。旧缓存用新类加载为 5.85 GiB，原类加载为 6.98 GiB；新序列化快照在单个真实 mzML 搜索中加载后为 5.00 GiB、搜索峰值 5.49 GiB，扫描 1,906 条结果用 34.21 秒。旧单进程正模式工作集约 7.25 GiB。进程容量估算设为每进程至少 6.5 GiB，另预留 3 GiB。数字取自 Windows 工作集实测，其他数据和配置仍需以实际机器内存为准。

MS-DIAL 的源码使用按 RT/m/z 搜索的对齐主峰并给每个文件设置成员；LipidIN 官方 Python 库是更大规模的 pickle 理论库，官方要求至少 16 GB RAM。库规模、字段和任务不同，不能把两者的总内存数字直接作为本软件的性能判据。这里选择缩减现有对象开销并保留源码行为和候选审核路径。

## 结果行与 ECN

MS1 的跨文件峰继续按 OpenMS 对齐 ID 合并。没有 MS1 峰的扫描只按 5 ppm、0.08 min 与离子模式做保守归组，使用完整跨度限制，避免连续相邻扫描一路串联；页面和导出特征表为一组一行，逐谱表保留每条扫描。截图中的三个 LPC(14:0) 扫描 `scan_1291`、`scan_1478`、`scan_1344` 归为 `MS2-00069`，支持 3 个样本；中位 RT 5.476033 min、中位 m/z 468.307258。此 ID 是本次审计表中的推测性谱簇 ID，不代表已确认的 MS1 色谱峰。相同 m/z、RT 的共洗脱异构体仍可能需要人工复核。

ECN 页面分开控制启用过滤、RT 阈值和是否保留拟合点数不足的亚类。保留时动作记为 `retain_unmodeled`，状态为“无法判断”；关闭时不进入通过结果。结果查看页的导出对话框集中提供当前筛选/全部、CSV、Excel、ECN 图像、DPI 和阈值带设置。

## LPS 目标谱复核

正模式 MSP 源库中 164 条 LPS `[M+NH4]+` 已移除，并在运行时额外排除；保留的备份位于统一测试目录。样本 04 的 `scan_1422`，RT 5.798933 min，母离子 m/z 524.297865：库内 LPS(18:1) `[M+H]+` 质量误差 -0.83 ppm，m/z 339.292258 对理论 339.2894 的误差 +8.42 ppm，得分 75；这张谱没有 18:1 脂酰链峰。相邻 `scan_1409`，RT 5.767767 min，母离子 m/z 524.297050：m/z 339.288899 的误差 -1.48 ppm，18:1 脂酰链 m/z 265.250087 对理论 265.2526 的误差 -9.47 ppm，得分 83.33。两张谱均为 MS2-only；同一推测性谱簇跨四份文件有 7 张谱。

在 10 ppm 母离子窗口内另有 PS-O、LPG 与 LCE-PE 候选。用两张已保存的实验谱逐一复算，PS-O 仅得到共用头基丢失碎片、约 20 分；LPG 和 LCE-PE 缺少诊断碎片、为 0 分。因此现有库和规则下 LPS(18:1) 最有支持，但 5.799 min 这张谱单独不能确认 18:1 链，也不能分辨 `LPS(18:1/0:0)` 与 `LPS(0:0/18:1)` 位置异构体；结果应维持低置信度/待人工复核。

完整测试：619 passed、3118 subtests passed。真实四文件旧结果的 8,510 条候选在新浏览器中合成 2,321 行特征；三张 LPC 谱在导出特征表仅一行，逐谱证据均保留。新正模式库对样本 04 搜索仍为 1,906 条结果，逐行注释、分数和匹配碎片与旧库完全一致，两张目标谱仍返回 LPS(18:1)。
