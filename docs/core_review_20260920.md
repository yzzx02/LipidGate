# LipidGate 核心审查与固定基线（2026-09-20）

本轮覆盖谱库、MS2 门控与评分、MS1 关联、结果导出、ECN 筛选/图像及 GUI 项目流程。发现的产品连接和参数传递问题已修复；本轮验证未发现阻止正常 pyOpenMS 项目流程运行的问题。固定的是可核对的代码、谱库及默认参数基线，不是对所有脂质鉴定正确性的保证。

## 已修复的问题

| 问题 | 修正及影响 |
| --- | --- |
| GUI ECN 仍调用早期算法 | 新项目统一走 `pipeline.py` → `final_results.py` → 高置信度、有序系列模型，包含已确认的真实两点规则。原 `ecn-filter` 仅作兼容入口，新 CLI 为 `filter-results`。 |
| 后台任务读取运行中的控件 | 开始前保存参数快照；后台只读取快照。回调明确排入 Qt 主线程，任务结束前锁定参数与项目切换，避免跨线程更新控件及重复启动。 |
| Da → ppm 切换误把误差夹为 0.1 ppm | 切换单位时设置相应默认值；项目恢复随后填回保存值。用户设定的 10/10 ppm 能正确传到匹配器。 |
| Asari/XCMS 没跟随负模式选择 | MS1 的 `mode`/`polarity` 从项目离子模式传递，不沿用正模式默认值。 |
| 多文件对齐合并边界用于单文件 MS2 关联 | pyOpenMS 在 RT 变换之前保存各文件原始峰顶、边界及来源。对齐表保留用于样本间整理，MS2 使用 `_native.csv`，按文件匹配，避免另一文件的峰或合并范围提供虚假的 MS1 支持。 |
| 错模式谱库仍可能产生同质量候选 | 项目执行前检查 mzML 离子模式；搜索器根据实验极性及加合物电荷符号拒绝反模式候选，缺少电荷数时也生效。 |
| 空结果、过滤后无候选时导出不稳 | 空表仍输出完整的 17 列工作簿；分数不通过、ECN 不通过、RT 未判定在审计表中分开记录。 |
| 新 ECN 状态名不能被旧画图入口识别 | 当前模型按 `RT_consistency_pass` 取点，优先使用本次筛选的实际 RT；不再对未建模系列偷偷重拟合一条展示曲线。 |
| 项目参数与历史页面逻辑重复 | 参数页与执行入口分离，去掉旧独立运行/ECN 按钮；保存、恢复项目，清除上一项目的表格，输出按运行目录隔离。 |

多文件 MS1 输入优先在源数据同卷临时目录中使用硬链接；只有无法链接时才复制，避免大文件无必要地跨盘复制。临时目录会自动清理。

## 谱库与既有规则

对两个完整库检查了记录数、头信息、前体/碎片数值、声明峰数与实际峰数，以及 gzip 解压内容与原始 MSP 的 SHA-256 一致性。结果：

| 谱库 | 记录数 | 结构检查 | 压缩/原文一致 | PS `[M+NH4]+` |
| --- | ---: | --- | --- | ---: |
| positive | 1,249,784 | 通过 | 是 | 0 |
| negative | 1,084,782 | 通过 | 是 | 0 |

库文件本轮没有再修改。保留此前确认的化学规则，包括“库里存在 HG 才检查 HG”的条件门控、正模式链碎片计数/覆盖规则、PC-P 例外、PC-Na、PE-Cer、氧化链证据和 TG-EST 输出限制。谱图极性保护不改变同模式候选的评分公式。

默认 MS2 参数仍为母离子 5 ppm、碎片 15 ppm、相对强度 0.2%、Top 3；分数过滤默认开启且为 50 分。用户可设置 10/10 ppm，配置会随项目保存。关闭分数过滤时不再先被后台固定的 50 分阈值截断；化学证据门控继续运行。

## 导出和 ECN / 图像基线

- 最终工作簿三个页：最终鉴定（每个类别/名称选代表记录）、逐谱证据、RT 未判定。保留 17 个核心字段；白色背景、黑字，数值仍是 Excel 数值。完整候选/筛选原因/模型/实际支持点保存在审计 CSV，不挤入展示表。
- 默认 Top 3 表示保留各谱图的候选供后续过滤，不表示最终仅 Top 1。ECN 可以回捞符合已建立模型的低置信度记录，但不会把其 MS2 置信度改为高。
- ECN 默认关闭；开启后按高置信度、有序系列规则处理，阈值默认 ±0.5 分钟。通过验证的两点系列连接实际观测点，三点/单点沿用已确认的邻近系列支持规则；无法评估的记录不冒充通过。
- 普通项目用本文件原始 MS1 峰顶；缺乏支持时用 MS2 采集 RT。不会套用本地二维数据的分段偏移，也不会把拟合预测值写成实验 RT。
- 图像保持固定 DB 颜色，白底，单图 4.0 × 3.45 英寸、默认 300 DPI；每个 DB/C 展示残差最小的实际保留点，可选择绘制阈值带，图例与曲线颜色一致。导出散点 CSV 可追溯展示点。

## GUI 与真假峰模块

顺序为：项目 → 导入文件 → MS1 参数 → MS2 参数（模式、谱库、误差、强度、加合物、类别、Top N）→ 分数/ECN 过滤与导出 → 结果查看。

项目内只登记输入路径，运行前才检查类型和单一离子模式；当前引擎仍读取 mzML。项目文件为 `lipidgate.project.json`，每次运行在 `runs/时间戳/` 保存参数、代码指纹、输入路径/大小/修改时间及谱库哈希。GUI 与 `project-run` 共用同一执行函数。

真假峰识别已移出 `src/lipidgate/`，移除 GUI、CLI 入口及 torch/torchvision 依赖。原代码/测试归档在 `archive/peak_truth/`，历史模型保留本地；两者从发布归档中排除。真实 MS1 特征支持仍由特征检测结果提供，不需要另一个真假峰分类器。

## 固定与复核

`config/core_baseline_20260920.json` 保存当前有效代码指纹、谱库哈希、默认参数和固定 DB 色表。保持参数可调，不给源文件加只读锁。

```powershell
python scripts/audit_core_baseline.py --output config/core_baseline_20260920.json --check
python -m pytest -q
```

`--check` 只检查，不改基线；核心源码、默认参数或谱库发生变化会明确报错。未来有意修改后，应先验证再重新审计生成基线，并在变更记录中说明影响。
