# MS1 gap filling

源码开发版在跨样本对齐后，从原始 MS1 恢复漏检峰的面积。GUI 的「MS1 特征」页提供
「启用 Gap filling」开关，默认开启；`lipidgate project-run` 使用同一组保存参数。
已完成的旧运行不会自动重新补峰，发布的 v1.0.3 EXE 尚未包含此功能。

## 方法与参考实现

核对了以下固定提交的源码：

- [XCMS `ChromPeakAreaParam` 补峰](https://github.com/sneumann/xcms/blob/b781f8b0c39a3310d74aebe5ae59d24f7e818431/R/methods-XCMSnExp.R#L2637)：
  分组后，仅对缺失的样本/特征组合提取原始信号，并保存 `is_filled`。其默认区域由各
  检出峰边界的分位数构成；采用校正后的扫描时间进行区域提取。
- [MS-DIAL LC-MS gap filler](https://github.com/systemsomicslab/MsdialWorkbench/blob/349d7ef6edbd09e34c0eb38b849bd9fd8af79e7e/src/MSDIAL5/MsdialLcMsApi/Algorithm/Alignment/LcmsGapFiller.cs#L42)：
  根据已有峰确定目标质量、时间和宽度；逆变换到原始时间后寻找附近的峰顶和边界，
  对边界内信号积分，保留补峰状态；另有可选的强制插入分支。

LipidGate 的 `targeted_eic_v1` 是参考上述思路的独立实现，复用本项目已有的 EIC
分峰算法，没有复制第三方代码，也不声称与 XCMS 或 MS-DIAL 的数值完全相同：

1. 保留原始检测表和对齐表；仅检查面积为空或为 0 的样本单元格。该样本已有原生
   检测峰时不补，已有正面积不覆盖。无效负面积、无穷值保留原值并记录原因。
2. 使用保存的 **raw→aligned RT 映射的逆变换** 读取该样本自己的原始窗口。窗口
   上下文参考对齐峰宽；候选峰顶必须位于配置的 RT 容差内。仅在实测采集范围内
   插值，不外推；不假设原始 RT 与对齐 RT 相同。
3. 提取质量窗口内最近的 centroid m/z 信号。平滑仅用于找峰和谷底；峰宽、信噪比、
   多扫描支持及扫描连续性必须合格。原始峰顶两侧各需至少两张扫描。
4. 以同文件实测谷底区分邻峰；相近且同等合理的候选保持缺失。不占用已属于其他
   原生峰的信号，同一原始峰也不能填到两个不同特征行。
5. 用未平滑的原始强度和实际扫描时间做梯形积分，单位为 `intensity*seconds`。
   同时记录直线边界基线扣除后的面积。主矩阵使用零基线面积，以保持与原生
   pyOpenMS 定量一致；不补造扫描点，不按名义窗口宽度放大面积，不强制插入噪声。

这一步只恢复 MS1 定量。它不生成原生 Feature ID，不改变检测峰边界、MS2 关联、
分数、gate、候选顺序、逐谱置信度或合格 Top1 的样本投票。只有某张 MS2 自身具有
对应证据时，它才可能支持鉴定；补出的面积不能独立证明某样本已经鉴定该脂质。

## 参数与后端

| 参数 | 默认 | 含义 |
| --- | ---: | --- |
| `enabled` | `true` | 对新运行启用补峰；关闭 MS1 时跳过 |
| `mz_ppm` | 5 | 原始 MS1 质量容差 |
| `rt_tolerance_sec` | 10 | 对齐时间轴上的峰顶容差，逆映射到各样本 |
| `min_snr` | 3 | 目标 EIC 的最低稳健信噪比 |
| `min_fwhm_sec` | 3 | 原始时间轴上的最低 FWHM |
| `max_fwhm_sec` | 60 | 最高 FWHM |
| `min_height` | 0 | 可选最低峰高，不沿用全局检测的噪声门槛 |

GUI 暴露开关、质量误差、RT 容差及信噪比；其余参数可保存在项目 JSON 的
`settings.ms1.gap_filling` 中，GUI 再次保存时保留。例如：

```json
"gap_filling": {
  "enabled": true,
  "mz_ppm": 5.0,
  "rt_tolerance_sec": 10.0,
  "min_snr": 3.0,
  "min_fwhm_sec": 3.0,
  "max_fwhm_sec": 60.0,
  "min_height": 0.0
}
```

pyOpenMS 保存实际线性校正映射；XCMS 保存扫描级的原始/校正 RT 及原生峰成员。
XCMS 桥接脚本原来隐式调用 `fillChromPeaks()`，现由上述共享补峰阶段替代，以免丢失
补峰状态或重复填充。独立 `lipidgate detect` 只做检测/对齐，补峰由项目流水线执行。

Asari 或外部 MS-DIAL 表如果未提供可靠的原始 RT 映射，缺失单元格记录为
`missing_rt_mapping`，不直接将参考 RT 当成原始 RT。单样本原生峰表没有跨样本缺口，
本步骤不适用。没有检测锚点、无法校正的样本也保留缺失。Profile MS1 需要先质心化。

## 保存、展示与内存

每次运行在 `ms1/gap_filling/` 保存：

- `gap_filled_features.csv`：一行一个特征的完整面积矩阵及补峰样本。
- `gap_filling.csv`：每个尝试的样本/特征组合、成功/缺失/跳过/读取失败原因、
  目标坐标、实测峰顶和边界、S/N、FWHM、扫描数及积分。
- `filled_peaks.csv`：仅成功补峰的实测记录，供 EIC 按需读取。
- `gap_filling.json`：方法、参数、参考源码、文件身份和表/映射/审计 SHA-256。

正式 CSV / Excel 和 GUI 导出在原有样本列中使用补回的面积，并增加「补峰样本」和
「补峰样本数」。仍为一行一个特征，候选表不复制面积矩阵。GUI 详情区显示补峰来源，
选择补峰样本查看 EIC 时使用其实际峰顶和边界。MS1 检出样本数仍只按原始检测矩阵
统计，加合物关系与 MS2 关联继续读取原始检测表。

每个原始文件流式读取一次，只保留仍处于提取窗口内的紧凑 EIC 数组，不将整个
项目的扫描数组载入内存。提取窗口结束便释放 EIC；审计表、目标列表和输出矩阵
本身仍需要内存。浏览器仅缓存最多 128 个补峰坐标查询，不常驻全部补峰详情。

## 验证范围

回归覆盖弱峰、RT 偏移、原始扫描积分、邻峰谷底、重复占峰、原生峰保护、无信号、
噪声、尖峰、采集缺口、缺失/非单调 RT 映射、profile 数据、读取失败及 CSV/Excel
两条导出路径。实际 pyOpenMS 项目流水线对照开启/关闭补峰，检查面积恢复，同时
确认原始文件、原生检测成员、MS2 分数、gate、置信度和候选次序不受补峰影响。
本地还运行了真实 R/XCMS 检测、Obiwarp 校正和定向补峰的合成弱峰验证。

这些是实现正确性验证，尚不能代表复杂真实样本上的补峰灵敏度、定量偏差或 FDR。
后续可在有标准品和空白对照的数据上比较各方法的恢复率与误填率。
