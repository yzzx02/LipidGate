# 多文件 MS2 并行处理（2026-09-24）

## 代码对照与决策

- MZmine 的任务控制器把处理任务交给并行执行器；其谱库匹配任务持有明确的输入行和参数，并跟踪处理进度。参考：[任务架构](https://mzmine.github.io/mzmine_documentation/latest/coding/general_structure.html)、[谱库匹配任务源码](https://github.com/mzmine/mzmine/blob/master/mzmine-community/src/main/java/io/github/mzmine/modules/dataprocessing/id_spectral_library_match/RowsSpectralMatchTask.java)。LipidGate 没有移植 Java 任务框架，只借鉴独立任务与可观察进度的边界。
- Python `ProcessPoolExecutor` 使用独立进程，任务函数与参数须能被序列化，Windows 子进程需要能重新导入模块。参考：[官方文档](https://docs.python.org/3/library/concurrent.futures.html#processpoolexecutor)。实现使用模块顶层任务函数、`spawn`、每个进程一次谱库初始化，只向子进程发送路径和搜索参数。
- 本项目先前对真实 mzML 的双线程对照中，负模式 115.80→159.24 秒，正模式 127.60→131.60 秒，均未提速；逐行结果一致。因此没有把线程方案接入正式流程，见 [原实验记录](final_2d_20260913.md#并行与耗时)。

## 实现边界

GUI 的「MS2 处理进程数」可选 1–4，默认 1；设置随项目保存。仅多文件 MS2 检索并行。每个进程持有自己的谱库和 mzML 读取状态，处理多个文件时复用搜索器；主进程按原文件顺序合并结果，并继续执行脂质名解析、MS1 特征关联、去重、分数/ECN 筛选及导出。单文件不启动进程池。文件完成时报告进度；子进程错误直接上报，不自动回退成另一种分析结果。

上限为 4 个进程。正式正模式谱库的本机解析缓存约 0.8 GB。四进程试验时各工作进程的工作集已达约 5–6 GB，32 GB 本机的空闲内存降至约 0.9 GB，因此中止；三进程完成时各进程约 7.2 GB、空闲内存最低约 4.5 GB。不能把缓存文件大小当作进程内存。进程池按所选数量分别加载谱库，不在主进程再加载一次。启动前按缓存或谱库大小估算每进程内存（当前约 7.3 GB），额外预留 3 GB；若当前可用内存不足则拒绝启动并提示减少进程数。估算不是峰值保证。进程数写入运行设置与 MS2 结果参数，原有鉴定、评分和门控规则不变。

## 结果与速度

在 Windows、16 逻辑处理器、32 GB 内存的本机，用正式正模式谱库和两份约 116–117 MB 的 mzML 对照。设置：前体 5 ppm、碎片 15 ppm、峰强度 0.2%、最低分 50、Top 3。串行和双进程的每个文件结果 DataFrame `check_exact=True`，候选与前体校正审计一致。小型真实 mzML 的完整工作流测试也确认双进程与串行导出审计逐项一致。

| 运行 | 单进程 | 双进程 | 解释 |
| --- | ---: | ---: | --- |
| 第一轮 | 180.41 秒 | 48.14 秒 | 串行先运行，承担冷缓存成本，不能据此算加速比 |
| 第二轮 | 35.59 秒 | 192.88 秒 | 缓存已热，双进程反而明显慢 |

双进程收益对缓存、谱库加载和内存竞争敏感。两文件样本没有支持默认开启并行的稳定证据，所以默认 1；较大批次可自行比较运行时间后再选 2。

## LargeIntestine 正模式真实批次补测

从 `D:\脂质匹配算法软件\dataset\LargeIntestine\Pos` 的 46 份 mzML 中，按文件大小分层选取 8 份（包含 QC 和 Blank），每份约 123–142 MB。为绕开本机 pyOpenMS 对中文目录的读取问题，使用同一磁盘的临时英文路径硬链接；没有复制或修改原始文件。前体 5 ppm、碎片 15 ppm、相对强度 0.2%、最低分 0、Top 3 与正式项目搜索一致。

单进程 468.05 秒，双进程 196.44 秒（约 2.38 倍）；八份文件的结果行数分别为 2166、2022、1901、1771、1805、121、1530、1847，逐文件 DataFrame `check_exact=True`。这是一次顺序对照，不能代表所有硬件与样本；但说明在较大批次上双进程有实际收益。单文件仍固定串行，默认进程数仍为 1，由用户按内存与批次规模选择 1–4。

在同一组 8 份文件上，三进程为 139.73 秒，逐文件行数与上面的串行/双进程对照相同。四进程因内存压力中止；提高预检阈值后会在本机创建工作进程之前拒绝四进程。所有临时基准脚本、硬链接、JSON、CSV 和试运行结果集中在 `.test_outputs/parallel_tests_20260924/`，用户可自行删除该目录。
